# アプリ / ウェブサイト知識パック

NestSpace は、一般的なアプリやウェブサイトをカバーする、簡潔で手作業で作成された中国語の使用ガイドを AI アシスタント用に用意しています。アシスタントがあるアプリやページに初めて入ると、対応するガイドがツール結果に注入されます。それ以外のときはプロンプトを占有しません。

現在の内蔵内容：

- 23 個のアプリ：支付宝、高德地图、哔哩哔哩、BOSS直聘、DeepSeek、钉钉、抖音、飞书、京东、快手、美团、12306、拼多多、QQ、QQ邮箱、淘宝、腾讯视频、今日头条、微信、微博、闲鱼、小红书、知乎。
- 19 個のウェブサイト：12306、支付宝、高德、哔哩哔哩、携程、DeepSeek、抖音、饿了么、京东、快手、美团、网易云音乐、拼多多、QQ、淘宝、微博、小红书、知乎、BOSS直聘。

## ディレクトリ構造

```text
app/src/main/assets/knowledge/
  apps/<id>/APP.md
  sites/<domain>/SITE.md
```

- `apps/<id>` は `bilibili`、`pinduoduo` のような安定した短い名前を使用します。
- `sites/<domain>` は `bilibili.com`、`jd.com` のような登録可能なドメインを使用します。
- ディレクトリ名は front matter の `name` / `domains` と一致させる必要があります。

## ファイル形式

### アプリガイド

```markdown
---
name: bilibili
display: 哔哩哔哩
packages: [tv.danmaku.bili]
aliases: [B站, 哔哩哔哩, bilibili]
domains: [bilibili.com]
---
## 是什么
一两句话说明这个应用是做什么的。

## 入口与常见路径
- 稳定的入口名称、Tab 名称、页面标题。
- 常见的 URL 规则或搜索路径。

## 注意
- 需要登录、验证码、支付或用户确认的步骤。
- 有风险或不可逆的操作。

## 怎样算完成
- 用什么页面或文字可以判断任务完成。
```

### ウェブサイトガイド

```markdown
---
name: bilibili.com
display: 哔哩哔哩网页版
domains: [bilibili.com]
---
## 是什么
...
```

ウェブサイトガイドでは `packages` の代わりに `domains` を使用します。

## フィールドの説明

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `name` | はい | 一意の識別子。アプリは短い名前、ウェブサイトはドメインを使用 |
| `display` | はい | ユーザーに表示する名前 |
| `packages` | アプリは必須 | Android のパッケージ名。複数指定可能 |
| `aliases` | いいえ | 別名。マッチングと表示に使用 |
| `domains` | ウェブサイトは必須 | 登録可能なドメイン。複数指定可能 |

ルール：

- アプリガイドには `packages` が必須です。ウェブサイトガイドには `domains` が必須です。
- パッケージ名とドメインは、すべてのガイドの中で一意である必要があります。
- 本文は 4000 文字以内に収めてください。そのまま注入されます。

## 作成の原則

- **安定している**ものを記述します。ボタンのテキスト、タブ名、URL のルール、ページタイトルなどです。座標、価格、一時的な内容を固定値で書かないでください。
- どのステップでユーザーの関与が必要かを明確にします。ログイン、認証コード、支払い、権限、メッセージ送信、データ削除などです。
- アシスタントに認証コード、ログイン、支払い確認、プラットフォームの制限を回避する方法を教えないでください。
- 「完了条件」を明確に記述します。どのページが表示されるか、どのテキストが出るかなどです。
- 現在の画面は常にガイドより優先されます。ガイド内にその旨を明記してもかまいません。

## マッチングと注入

`KnowledgeStore` は実行時にこれらのファイルを読み込み、次のようにマッチングします。

- `space_launch` / `space_multi_open`：パッケージ名でマッチング。
- `ui_observe`：`package` パラメータまたは現在のスナップショットのパッケージ名でマッチング。
- `browser_open` / `browser_navigate`：結果 URL の host でマッチングし、最も具体的なドメインが優先されます（`search.bilibili.com` は `bilibili.com` にマッチ）。

マッチしたガイドは：

- JSON 結果の `guide` フィールドとして返される。
- またはプレーンテキストの結果の後ろに付加される。
- 実行ごと（ローカルアシスタント）、または MCP セッションごとに 1 回だけ注入され、コンテキストの重複占有を避けます。

## ガイドの追加

1. ディレクトリを作成します：

   ```text
   app/src/main/assets/knowledge/apps/<id>/APP.md
   app/src/main/assets/knowledge/sites/<domain>/SITE.md
   ```

2. front matter と本文を記入します。
3. 知識パックのテストを実行します：

   ```bash
   ./gradlew :app:testDebugUnitTest --tests com.coke.nestspace.knowledge.KnowledgePackTest
   ```

4. APK を再ビルドします。インデックスやコードを変更する必要はありません。

## よくある質問

### ガイドが注入されない

- パッケージ名またはドメインが front matter と完全に一致していることを確認します。
- 本文が 4000 文字を超えていないことを確認します。
- `ui_observe` には正しい `package` を付けるか、ページスナップショット自体にパッケージ名がある必要があります。
- ブラウザは host でマッチングするため、URL のドメインが `domains` に含まれていることを確認します。

### ガイドの内容が長すぎる

安定した入口、注意事項、完了条件のみを残してください。詳細な手順は、アシスタントが現在の画面を観察して判断します。

### 複数のガイドが同じページにマッチする

ドメインのマッチングでは最も具体的なものが選ばれます。パッケージ名は一意に保ち、同じパッケージ名が複数のガイドに現れないようにしてください。
